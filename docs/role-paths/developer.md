# Developer Path

## Purpose

Help engineers derive and verify lineage from technical artifacts.

## When to use

Use this path when you implement lineage extraction, transformation parsing, or quality checks.

## Inputs

- Source code
- Configuration files
- Schema definitions
- Optional runtime logs

## Steps

1. Read [Evidence model](../core-concepts/evidence-model.md).
2. Read [Derivation lifecycle](../core-concepts/derivation-lifecycle.md).
3. Explore the unfinished [first lineage slice](../how-to/build-first-lineage-slice.md).
4. Review [lineage quality criteria](../how-to/validate-lineage-quality.md).
5. Read [Architecture Decision Records](../adr/index.md) for design rationale.
6. Use source papers in [Reference](../Universal_Semantic_Lineage_Architecture.md) for design depth.

## Output

You understand the extension points and current limitations; examples are not yet fully runnable.
